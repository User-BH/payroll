| پارامتر | مقدار (ریال) |
|---|---|

| پایه سنوات روزانه | ۱۶۶٬۶۶۷ (ماهانه ۵٬۰۰۰٬۰۱۰) |

| حق تاهل ماهانه | ۵٬۰۰۰٬۰۰۰ |
| حق اولاد هر فرزند | `۳ × حداقل دستمزد روزانه` = ۱۶٬۶۲۵٬۵۵۰ |
| روزهای ماه (شش‌ماههٔ اول) | ۳۱ |

| ضریب اضافه‌کاری | ۱٫۴ |

| مرخصی استحقاقی سال | ۲۶ روز |
| سقف انتقال مرخصی از سال قبل | ۹ روز |

### فرمول افزایش مزد ۱۴۰۵

```
مزد روزانه ۱۴۰۵ = ROUND( مزد روزانه ۱۴۰۴ × ۱٫۴۵ + ۵۱۹٬۵۴۹ , 0 )
```

همین فرمول روی حداقل دستمزد ۱۴۰۴ هم می‌نشیند:
`۳٬۴۶۳٬۶۵۶ × ۱٫۴۵ + ۵۱۹٬۵۴۹ = ۵٬۵۴۱٬۸۵۰` — یعنی «۴۵٪ + مبلغ ثابت»، همان
مصوبهٔ شورای عالی کار.

## ۴. بدنهٔ فیش — ستون به ستون

### کارکرد

```
کارکرد واقعی ماهانه = روزهای ماه − (غیبت + بدون حقوق + بیماری)
```

مرخصی استحقاقی و مأموریت **کسر نمی‌شوند**.

### مزد و سنوات

```
مزد روزانه            S = ROUND(مزد روزانه ۱۴۰۴ × ۱٫۴۵ + ۵۱۹٬۵۴۹)
جمع مزد و سنوات روزانه U = پایه سنوات روزانه + S
حقوق ماهانه            V = S × ۳۰                     ← همیشه ۳۰، نه طول ماه
پایه سنوات ماهانه      W = پایه سنوات روزانه × کارکرد
جمع حقوق و سنوات ماهانه X = V + W                     ← مبنای اضافه‌کاری و کسر کار
حقوق قابل پرداخت      AA = S × کارکرد
سنوات قابل پرداخت     AB = پایه سنوات روزانه × کارکرد
```

> **نکته:** `V` (که فقط در `X` و در ماخذ کسر کار به کار می‌رود) روی ۳۰ روز
> بسته شده، ولی `AA` (که روی فیش پرداخت می‌شود) روی کارکرد واقعی. در ماه
> ۳۱ روزه این دو عدد یکی نیستند.

### مابه‌التفاوت پایه سنوات تجمیعی

```
پایه سنوات تجمیعی ماهانه Z = ROUND(پایه سنوات تجمیعی روزانه × کارکرد)
مابه‌التفاوت            AD = MAX(Z − AB , 0)
```

`AD` عدد کلیدی این سیستم است: هم روی فیش پرداخت می‌شود و هم **اولین چیزی است
که از مازاد/پورسانت کسر می‌شود**.

> پایهٔ سنوات تجمیعی روزانهٔ ۱۴۰۵ برای ۳۰ نفر از ۳۳ نفر **دستی تایپ شده**؛
> فرمول `ROUND(مقدار ۱۴۰۴ × ۱٫۳۲)` فقط روی ۳ سطر اجرا شده و با اعداد دستی هم
> نمی‌خواند. → سؤال شمارهٔ ۱ در بخش پایانی.

### مزایای ماهانه — تسهیم فقط زیر ۳۰ روز

```
اگر کارکرد = ۳۰ یا ۳۱  →  مبلغ کامل
وگرنه                   →  ROUND(مبلغ کامل ÷ ۳۱ × کارکرد)
```

روی حق مسکن، حق اولاد، حق تاهل و وجه بن. (در فروردین مخرج ۳۰ بود؛ از اردیبهشت
اصلاح شد.)

### اضافه‌کاری

```
نرخ هر ساعت  = X ÷ ۲۲۰ × ۱٫۴
نرخ هر دقیقه = X ÷ ۱۳۲۰۰ × ۱٫۴
مبلغ = ROUND(نرخ ساعت × ساعت + نرخ دقیقه × دقیقه)
```

### مأموریت

```
گروه فروش    : مبلغ = روز × U × ۲
گروه پشتیبانی: مبلغ = روز × U        (روز از زنجیرهٔ بخش ۵)
```

### جمع پرداختی‌ها

```
جمع پرداختی فیش = حقوق + سنوات + مابه‌التفاوت سنوات + حق مسکن + حق اولاد
                + حق تاهل + وجه بن + اضافه‌کاری + وجه مرخصی + پایان‌کار
                + عیدی + مأموریت + پورسانت ۱ و ۲ و ۳ + طلب ماه قبل
```

### مالیات

```
ماخذ مالیات = جمع پرداختی − مبلغ مأموریت
```

پلکان ماهانهٔ ۱۴۰۵ (ریال):

| از | تا | نرخ | مالیات انباشته |
|---|---|---|---|
| ۰ | ۴۰۰٬۰۰۰٬۰۰۰ | معاف | ۰ |
| ۴۰۰٬۰۰۰٬۰۰۰ | ۸۰۰٬۰۰۰٬۰۰۰ | ۱۰٪ | ۰ |
| ۸۰۰٬۰۰۰٬۰۰۰ | ۱٬۰۰۰٬۰۰۰٬۰۰۰ | ۱۵٪ | ۴۰٬۰۰۰٬۰۰۰ |
| ۱٬۰۰۰٬۰۰۰٬۰۰۰ | ۱٬۲۰۰٬۰۰۰٬۰۰۰ | ۲۰٪ | ۷۰٬۰۰۰٬۰۰۰ |
| ۱٬۲۰۰٬۰۰۰٬۰۰۰ | ۱٬۴۰۰٬۰۰۰٬۰۰۰ | ۲۵٪ | ۱۴۰٬۰۰۰٬۰۰۰ |
| ۱٬۴۰۰٬۰۰۰٬۰۰۰ | به بالا | ۳۰٪ | ۱۹۰٬۰۰۰٬۰۰۰ |

در هر پنج ماه، **هیچ‌کس مالیات نداشته** — بیشترین ماخذ حدود ۳۱۵ میلیون ریال
بوده و زیر سقف معافیت مانده است.

### بیمه

```
ماخذ بیمه = جمع پرداختی − (مبلغ مأموریت + حق اولاد)
سهم کارگر   = ROUND(ماخذ × ۷٪)
سهم کارفرما = ROUND(ماخذ × ۲۰٪)
بیمه بیکاری = ROUND(ماخذ × ۳٪)
```

**سقف بیمه اعمال نشده است.** بیشترین ماخذ ۳۱۵ میلیون ریال بوده و سقف قانونی
(۷ × حداقل دستمزد ماهانه ≈ ۱٬۱۶۴ میلیون ریال) هنوز فعال نشده، پس معلوم نیست
هنگام عبور از سقف چه انتظاری هست. → سؤال شمارهٔ ۳.

### کسر کار (تأخیر)

```
ماخذ کسر کار = V + W + حق مسکن + حق اولاد + حق تاهل + وجه بن
مبلغ = ROUND(ماخذ ÷ ۲۲۰ × ساعت تأخیر + ماخذ ÷ ۱۱۴۴۰ × دقیقه تأخیر)
```

> **۱۱۴۴۰ در برابر ۱۳۲۰۰.** نرخِ دقیقهٔ اضافه‌کاری بر ۱۳۲۰۰ (=۲۲۰×۶۰) بسته
> است، ولی نرخِ دقیقهٔ کسر کار بر ۱۱۴۴۰ (=۲۶×۴۴۰). دو مبنای متفاوت برای یک
> «دقیقه». → سؤال شمارهٔ ۲.

### جمع کسورات و خالص

```
جمع کسورات = مبلغ کسر کار + آزمایش و طب کار + جرائم خودرو + بیمه تکمیلی
           + بدهی متفرقه + بدهی ماه قبل + خرید از شرکت + قسط وام
           + بیمه سهم کارگر + مالیات + جمع علی‌الحساب [+ کسر انبار]
خالص پرداخت = جمع پرداختی − جمع کسورات
```

«کسر انبار» فقط از تیر به بعد. **علی‌الحساب پرداختی ماه، خودش یک قلم کسور است.**

## ۵. زنجیرهٔ مازاد → مأموریت → اضافه‌کاری (گروه پشتیبانی)

مهم‌ترین و پیچیده‌ترین بخش فایل. هدف: مبلغی که قرار است به پرسنل برسد
(مازاد ثابت + اضافه‌کار مازاد + اضافه‌کار واقعی + وجه مرخصی) با **کمترین بار
بیمه و مالیات** پرداخت شود — اول از راه مأموریت، بعد اضافه‌کاری.

```
۱) استخر     = اضافه‌کار واقعی + اضافه‌کار مازاد + مازاد ثابت + وجه مرخصی
۲) قابل تخصیص = استخر − مابه‌التفاوت پایه سنوات تجمیعی (AD)
۳) روز مأموریت = ROUNDDOWN(قابل تخصیص ÷ U)        ← U = مزد+سنوات روزانه
   مبلغ مأموریت = روز مأموریت × U
   ماندهٔ یک    = قابل تخصیص − مبلغ مأموریت
۴) نرخ ساعت = ROUND(X ÷ ۲۲۰ × ۱٫۴)
   ساعت اضافه‌کاری = ROUNDDOWN(ماندهٔ یک ÷ نرخ ساعت)
   مبلغ ساعت‌ها = ROUND(X ÷ ۲۲۰ × ۱٫۴ × ساعت)
   ماندهٔ دو    = ماندهٔ یک − مبلغ ساعت‌ها
۵) نرخ دقیقه = ROUND(X ÷ ۱۳۲۰۰ × ۱٫۴)
   دقیقهٔ اضافه‌کاری = اگر ماندهٔ دو < نرخ دقیقه → ۰
                      وگرنه ROUNDUP(ماندهٔ دو ÷ نرخ دقیقه)
   مبلغ دقیقه‌ها = ROUND(X ÷ ۱۳۲۰۰ × ۱٫۴ × دقیقه)
   ماندهٔ سه    = ماندهٔ دو − مبلغ دقیقه‌ها      ← معمولاً کمی منفی
```

**نمونهٔ واقعی — سید کمیل حجازی، فروردین:**

| گام | عدد |
|---|---|
| اضافه‌کار واقعی (۶۱ ساعت و ۳۰ دقیقه) | ۶۷٬۰۸۸٬۴۰۷ |
| مازاد ثابت | ۵۰٬۰۰۰٬۰۰۰ |
| استخر | ۱۱۷٬۰۸۸٬۴۰۷ |
| − مابه‌التفاوت سنوات | −۱۳٬۴۴۵٬۸۱۶ |
| قابل تخصیص | ۱۰۳٬۶۴۲٬۵۹۱ |
| ۱۸ روز مأموریت × ۵٬۷۰۸٬۵۱۷ | ۱۰۲٬۷۵۳٬۳۰۶ |
| ماندهٔ یک | ۸۸۹٬۲۸۵ |
| ۰ ساعت (نرخ ساعت ۱٬۰۹۰٬۸۶۸ > مانده) | ۰ |
| ۴۹ دقیقه × ۱۸٬۱۸۱ | ۸۹۰٬۸۷۶ |
| ماندهٔ سه | **−۱٬۵۹۱** |

`ROUNDUP` در گام آخر باعث می‌شود همیشه کمی **بیشتر** پرداخت شود؛ ماندهٔ سه
منفی می‌ماند و در فایل جایی نمی‌رود. عدد کوچک است ولی سیستماتیک است.

### گروه فروش

```
پورسانت یک قابل پرداخت = (پورسانت یک + مازاد ثابت)
                        − (مابه‌التفاوت سنوات + ذخیرهٔ پورسانت
                           + کسر مازاد پرداختی + مبلغ مأموریت)
```

روزهای مأموریت اینجا **دستی** انتخاب می‌شود، پس اگر بیش از ظرفیت انتخاب شود
عدد منفی می‌شود (نمونه: علی قاسمی، اردیبهشت، −۹۸۰٬۸۴۳).

## ۶. زنجیرهٔ مرخصی

```
انتقالی از ۱۴۰۴ = MIN(مانده تا آخر ۱۴۰۴ ، ۹)          ← سقف ۹ روز
قابل استفاده    = استحقاق سال (۲۶) + انتقالی
```

همه‌چیز به **دقیقه** حساب می‌شود (روز = ۴۴۰ دقیقه) و روز/ساعت/دقیقه با
`ROUNDDOWN` از دقیقه ساخته می‌شوند:

```
کل دقیقه = روز×۴۴۰ + ساعت×۶۰ + دقیقه
روز  = ROUNDDOWN(کل ÷ ۴۴۰)
ساعت = ROUNDDOWN((کل − روز×۴۴۰) ÷ ۶۰)
دقیقه = کل − روز×۴۴۰ − ساعت×۶۰
```

و مانده:

```
مانده دقیقه = قابل استفاده×۴۴۰ − مصرفی کل تا این ماه
```

دو ستون موازی نگه داشته می‌شود: «مصرفی ماه» و «مصرفی تا این ماه» — هر دو
به‌صورت اعلامی (ورودی) و واقعی (محاسبه‌شده).

## ۷. مغایرت‌های پیداشده

هر هفت مورد، جایی است که فرمول با عدد دستی جایگزین شده:

| ماه | سطر | نفر | مورد |
|---|---|---|---|
| اردیبهشت | ۲۲ | احد تقوایی ساقصلو | «انتقالی از ۱۴۰۴» دستی ۰ شده (باید ۹ می‌شد) و «استحقاق سال» ۳ به‌جای ۲۶ → **مانده مرخصی منفی ۴ روز** |
| خرداد | ۲۹ | مهسا تبادلی | «دقیقهٔ اضافه‌کاری محاسبه» دستی ۵۰ شده به‌جای فرمول (فرمول ۵۱ می‌داد) |

- **علی قاسمی، اردیبهشت:** پورسانت قابل پرداخت −۹۸۰٬۸۴۳ (یک روز مأموریت
  بیشتر از ظرفیت انتخاب شده).
- **فروردین:** مخرج تسهیم مزایا ۳۰ بوده در حالی که ماه ۳۱ روز است.

## ۷ب. بررسی دوم — «آیا همهٔ مبناها روی مزد روزانه است؟»

نه. بازبینی دوم روی هر ۱۶۵ نفر-ماه انجام شد و مبنای هر قلم دقیقاً مشخص شد.
**مزد روزانه مبنای پنج قلم است، نه همه.** سه قلم مبلغ ماهانهٔ ثابت‌اند و یکی
روی حداقل دستمزد می‌نشیند، نه روی مزد خود فرد:

| قلم | مبنا | رابطه | تأیید |
|---|---|---|---|
| حقوق ماهانه | مزد روزانه | `S × ۳۰` | ۱۶۵/۱۶۵ |
| حقوق قابل پرداخت | مزد روزانه | `S × کارکرد` | ۱۶۵/۱۶۵ |
| سنوات قابل پرداخت | سنوات روزانه | `T × کارکرد` | ۱۶۵/۱۶۵ |
| ماخذ اضافه‌کاری | هر دو | `S×۳۰ + T×کارکرد` | ۱۶۵/۱۶۵ |
| مأموریت | مزد + سنوات روزانه | `روز × (S+T) × ضریب` | ۱۶۵/۱۶۵ |
| **حق اولاد** | **حداقل دستمزد روزانه** | `تعداد × حداقل × ۳` | ۱۶۵/۱۶۵ |
| **حق مسکن** | **مبلغ ماهانهٔ ثابت** | ۳۰٬۰۰۰٬۰۰۰ برای همه | — |
| **وجه بن** | **مبلغ ماهانهٔ ثابت** | ۲۲٬۰۰۰٬۰۰۰ برای همه | — |
| **حق تاهل** | **مبلغ ماهانهٔ ثابت** | ۵٬۰۰۰٬۰۰۰ فقط متأهل | — |

نکتهٔ مهم دربارهٔ **حق اولاد**: مبنایش حداقل دستمزد روزانه است، نه مزد روزانهٔ
خود فرد. یعنی کسی که مزدش بالاتر از حداقل است، حق اولادش با بقیه یکی است. اگر
این را با «مزد روزانهٔ فرد» پیاده کنیم، برای هر کسی که بالای حداقل است عدد
غلط می‌دهد.

**حق تاهل قانونی نیست** — سیاست شرکت است: مبلغی ثابت که فقط به متأهل‌ها
می‌رسد و مثل حق مسکن به نسبت کارکرد تسهیم می‌شود. در فایل، هر ۱۱ نفری که
«مجرد» علامت خورده‌اند صفر گرفته‌اند و هیچ استثنایی نیست. تعداد فرزند در آن
دخالتی ندارد (کسی با صفر فرزند و وضعیت متأهل، مبلغ کامل را گرفته است).

**تسهیم:** هر چهار قلم ماهانه با فرمول یکسان تسهیم می‌شوند و ۵۵۴ مبلغِ
تسهیم‌شدهٔ فایل، ریال‌به‌ریال با `مبلغ × کارکرد ÷ ۳۱` خواند.

### ضریب مأموریت: تأیید شد که به **واحد** بسته است

بازبینی دوم این را قطعی کرد: در هر پنج ماه، **همان ۱۱ نفرِ واحد فروش** ضریب ۲
دارند و **همان ۲۲ نفرِ واحد پشتیبانی** ضریب ۱ — بدون یک استثنا. ضریب در خودِ
فرمولِ هر سطر تایپ شده، پس در فایل جایی ثبت نشده که چرا. در سامانه این با
«دامنه شمول» قابل بیان است: یک قلم مأموریت با ضریب ۲ محدود به مرکز هزینهٔ
فروش، و یکی با ضریب ۱ برای بقیه.

### دو چیز که فایل دربارهٔ خودش می‌گوید

**۱) ستون «روز های ماه» قابل اعتماد نیست.** در یکی از ۱۶۵ سطر عدد ۱۵ نوشته
شده به‌جای ۳۱. فرمول‌ها به این ستون نگاه نمی‌کنند و همه‌جا ۳۱ را دستی
نوشته‌اند، پس فایل به خودش آسیب نزده — ولی معنایش این است که عدد ۳۱ در
فرمول‌ها **سخت‌کد** است. فایل هنوز به هیچ ماه ۳۰ روزه نرسیده (فروردین تا
مرداد همه ۳۱ روزه‌اند)، پس معلوم نیست از مهر به بعد چه می‌کنند. سامانه طول
واقعی ماه را از تقویم می‌گیرد؛ این یعنی از مهر به بعد **عمداً** با فایل فرق
خواهد داشت مگر اینکه حسابدار بگوید ۳۱ باید بماند.

**۲) اقلام کسورات در طول سال اضافه می‌شوند.** «کسر انبار» در تیر به فرمول
جمع کسورات اضافه شده و در سه ماه اول نبوده. همان چیزی که کارشناس می‌خواست:
افزودن قلم تازه بدون دست بردن در فرمولِ همهٔ سطرها.

## ۸. سؤال‌هایی که باید با حسابدار روشن شود

1. **پایهٔ سنوات تجمیعی روزانهٔ ۱۴۰۵ از کجا می‌آید؟** ۳۰ نفر از ۳۳ نفر دستی
   تایپ شده‌اند و با فرمول `۱۴۰۴ × ۱٫۳۲` نمی‌خوانند. دو نفر با پایهٔ ۱۴۰۴
   یکسان، عدد ۱۴۰۵ متفاوت گرفته‌اند و برعکس. بدون قاعده، این عدد در سامانه
   فقط می‌تواند ورودی دستی بماند.
2. **دقیقهٔ کسر کار بر ۱۱۴۴۰ یا ۱۳۲۰۰؟** اضافه‌کاری از ۱۳۲۰۰ و کسر کار از
   ۱۱۴۴۰ استفاده می‌کند.
3. **سقف بیمه.** تا امروز کسی به سقف نرسیده؛ آیا هنگام عبور باید سقف اعمال شود؟
4. **ماندهٔ سه.** مبلغ کوچکی که به‌خاطر `ROUNDUP` بیشتر پرداخت می‌شود، جایی
   ثبت نمی‌شود. آیا باید در ماه بعد تسویه شود؟
5. **مأموریت گروه فروش با ضریب ۲.** تأیید شد که دقیقاً به واحد بسته است
   (بخش ۷ب)، ولی مبنایش در فایل ثبت نشده. آیا قاعده است یا توافق موردی؟
7. **مخرج تسهیم در ماه‌های ۳۰ روزه.** فایل همه‌جا ۳۱ را سخت‌کد کرده و هنوز به
   ماه ۳۰ روزه نرسیده. از مهر به بعد مخرج ۳۰ باشد یا همان ۳۱ بماند؟
6. **حقوق ماهانه روی ۳۰ روز.** آیا در ماه ۳۱ روزه، مبنای اضافه‌کاری و کسر کار
   باید همان ۳۰ روز بماند؟

## ۹. فاصلهٔ این روش با سامانهٔ فعلی

اقلام سامانهٔ عملیاتی با اقلام فایل مقایسه شد. **بیشتر اقلام از قبل هستند**؛
تفاوت اصلی این است که چند قلم در سامانه «ورود دستی»‌اند در حالی که در فایل
فرمول دارند.

### آنچه دقیقاً می‌خواند

- کارکرد = روزهای ماه − (غیبت + بدون حقوق + بیماری)
- تسهیم مزایای ثابت به نسبت کارکرد
- مالیات پلکانی ماهانه · بیمه با سه نرخ ۷٪ / ۲۰٪ / ۳٪
- **معافیت‌ها عیناً یکی است:** حق مأموریت معاف از بیمه و مالیات، حق اولاد معاف
  از بیمه — همان چیزی که فایل با `ماخذ مالیات = جمع − مأموریت` و
  `ماخذ بیمه = جمع − (مأموریت + حق اولاد)` می‌سازد
- مانده مرخصی بر مبنای دقیقه، روز = ۴۴۰ دقیقه
- اقلام کسور موجود: علی‌الحساب واریزی · خرید کالا · بدهی ماه قبل · سایر بدهی ·
  بیمه تکمیلی · آزمایش و طب کار · جرائم خودرو · کسر کار و تأخیر · وام
- اقلام مزایای موجود: حق تاهل · وجه مرخصی · طلب ماه قبل · مابه‌التفاوت ·
  پورسانت یک و دو و سه

### آنچه در سامانه دستی است ولی در فایل فرمول دارد

| قلم | فرمول فایل |
|---|---|
| مابه‌التفاوت پایه سنوات تجمیعی | `MAX(تجمیعی روزانه × کارکرد − سنوات قابل پرداخت، ۰)` |
| کسر کار و تأخیر ورود | `ماخذ ÷ ۲۲۰ × ساعت + ماخذ ÷ ۱۱۴۴۰ × دقیقه` |
| پورسانت یک قابل پرداخت (فروش) | `(پورسانت + مازاد ثابت) − (مابه‌التفاوت + ذخیره + کسر مازاد + مأموریت)` |

### آنچه اصلاً نیست

| موضوع | فایل شرکت | سامانه |
|---|---|---|
| فرمول افزایش مزد سالانه | `۱۴۰۴ × ۱٫۴۵ + ۵۱۹٬۵۴۹` | مزد قرارداد دستی وارد می‌شود |
| ترتیب تخصیص مازاد | مابه‌التفاوت → مأموریت → ساعت → دقیقه | مأموریت → اضافه‌کاری، بدون مابه‌التفاوت |
| گرد کردن تخصیص | `ROUNDDOWN` برای روز و ساعت، `ROUNDUP` برای دقیقه | تقسیم ساده |
| مأموریت گروه فروش | ضریب ۲ | ضریب ندارد |
| مبنای اضافه‌کاری | `مزد روزانه×۳۰ + سنوات روزانه×کارکرد` تقسیم بر ۲۲۰ | مبنای ساعتی ماه، وگرنه مزد ساعتی خود پرسنل |
| کسر انبار | قلم کسور جدا | با «قلم پارامتری» فاز ۷ ساختنی است |
| ماندهٔ سه (باقی‌ماندهٔ منفی تخصیص) | نگه داشته نمی‌شود | — |

### دو تفاوت مبنایی که باید تصمیم گرفت

۱. **گروه‌بندی محاسبه.** فایل، فروش و پشتیبانی را با دو الگوریتم متفاوت حساب
   می‌کند. در سامانه این می‌تواند «دامنهٔ شمول» قلم روی مرکز هزینه باشد
   (زیرساختش هست) یا دو قاعدهٔ جدا.

۲. **حقوق ماهانه روی ۳۰ روز.** فایل `مزد روزانه × ۳۰` را مبنای اضافه‌کاری و
   کسر کار می‌گیرد ولی `مزد روزانه × کارکرد` را پرداخت می‌کند. سامانه امروز
   همه‌جا از کارکرد واقعی استفاده می‌کند. این تفاوت روی مبلغ اضافه‌کاری اثر
   مستقیم دارد.
