# کارهای دستی بعد از هر به‌روزرسانی

`deploy/update.sh` کد و ساختار دیتابیس را به‌روز می‌کند، ولی **بعضی تغییرها به
یک عدد یا یک تیک نیاز دارند که فقط از پنل وارد می‌شود.** اگر آن قدم انجام نشود،
سامانه خطا نمی‌دهد — فقط آن قلم روی فیش نمی‌آید، و کسی نمی‌فهمد چرا.

این فایل فهرست همان قدم‌هاست، از تازه به قدیم. هر تغییری که ورودی دستی لازم
دارد باید همین‌جا یک سطر بگیرد، **در همان کامیتی که تغییر را می‌آورد**.

قاعده: بعد از هر به‌روزرسانی، از آخرین ردیفی که انجام نداده‌اید تا بالای فهرست
را انجام دهید، بعد دوره‌های باز را دوباره محاسبه بگیرید.

---

## مبنای اضافه‌کاری، مبنای مأموریت، و سابقه

**مهاجرت:** `employees.0008_prior_service` · `payroll_config.0010_…` ·
`attendance.0006_…`

**کار دستی — لازم:**

1. **گزارش سابقه را ببینید، پیش از هر محاسبه‌ای:**
   ```bash
   sudo -u www-data /srv/payroll/.venv/bin/python /srv/payroll/manage.py seniority_report
   ```
   سابقه دیگر عدد ثبت‌شده نیست و از تاریخ استخدام حساب می‌شود. کسی که عدد
   قدیمی‌اش کهنه شده بود ممکن است **از این ماه پایه سنوات بگیرد**. برای هرکس
   که سابقهٔ کار پیش از این استخدام دارد، «ویرایش پرسنل ← سابقهٔ قبلی (ماه)»
   را پر کنید.

2. **تنظیمات ← سال مالی**، سه کلید تازه (پیش‌فرضشان رفتار قبلی است):
   - «مبنای اضافه‌کاری» → برای این شرکت: **حقوق و سنوات ماهانه ÷ ساعات کار ماهانه**
   - «ساعات کار ماهانه» → ۲۲۰
   - «مبنای حق مأموریت» → برای این شرکت: **مزد روزانه + پایه سنوات روزانه**

3. **ضریب ۲ مأموریت فروش** (اگر می‌خواهید مثل فایل باشد): یک قلم دوم
   «حق ماموریت فروش» با نحوهٔ محاسبه «قاعده موتور»، کلید `mission_allowance`،
   نرخ ۲، و دامنه شمول مرکز هزینهٔ فروش. قلم مأموریت اصلی را هم به بقیهٔ مراکز
   محدود کنید، وگرنه هر دو با هم می‌آیند.

4. **قلم «کسر انبار»** اگر لازم دارید: تنظیمات ← اقلام حقوقی ← افزودن، نوع
   کسورات، نحوهٔ محاسبه «ورود دستی».

> بدون قدم ۲، محاسبه با روش قبلی ادامه می‌دهد و خطا نمی‌دهد — فقط اعداد با
> فایل اکسل نمی‌خواند.

## مزد روزانه به‌جای حقوق ماهانه

**مهاجرت:** `employees.0007_daily_wage` · **خودکار انجام می‌شود**

مزد قرارداد از ماهانه به روزانه تبدیل شد. مهاجرت عدد قدیمی را بر طول ماهِ آخرین
فیش صادرشده تقسیم می‌کند تا همان فیش عوض نشود.

**کار دستی — لازم:**

1. **پرسنل ← هر پرسنل ← ویرایش قرارداد**: عدد «مزد روزانه (ریال)» را یک بار
   چشمی ببینید. باید همان مزد روزانه‌ای باشد که در فایل اکسل دارید.
   اگر عدد قدیمی با مخرج دیگری وارد شده بود، اینجا معلوم می‌شود.
2. **تنظیمات ← سال مالی ← حداقل دستمزد روزانه**: پر باشد. هر قراردادی که مزد
   روزانه‌اش خالی است، از این عدد استفاده می‌کند.

> مزد روزانهٔ خالی **ایراد نیست** — یعنی «این پرسنل مزد اختصاصی ندارد».

## حق تأهل

**مهاجرت:** `payroll_config.0008_legalparameter_marriage_allowance`

**کار دستی — بدون این، حق تأهل روی هیچ فیشی نمی‌آید:**

1. ```bash
   sudo -u www-data /srv/payroll/.venv/bin/python /srv/payroll/manage.py \
       fix_component_wiring --apply
   ```
   قلم «حق تاهل» را از «مبلغ ثابت با مبلغ صفر» به قاعدهٔ موتور وصل می‌کند.
2. **تنظیمات ← سال مالی ← حق تأهل ماهانه**: مبلغ را وارد کنید (در فایل ۱۴۰۵
   شرکت: ۵٬۰۰۰٬۰۰۰ ریال). **صفر یعنی این قلم را ندارید** و سطرش نمی‌آید.
3. **تنظیمات ← اقلام حقوقی ← حق تاهل**: اگر دامنه شمولی دارد که به کسی نمی‌خورد
   (مثلاً «موقت» در حالی که همه دائم‌اند) حذفش کنید. صفحهٔ خلاصهٔ دوره حالا
   خودش این را هشدار می‌دهد.
4. **پرسنل**: وضعیت تأهل هر کس درست ثبت شده باشد — حق تأهل فقط به «متأهل»
   تعلق می‌گیرد.

## تیک «بازنشسته» → «بدون بیمه»

**مهاجرت:** `employees.0006_insurance_exempt` · **خودکار انجام می‌شود**

تیک‌های قبلی سالم منتقل می‌شوند و علتشان «بازنشسته» ثبت می‌شود.

**کار دستی — اختیاری:** برای کسی که به دلیل دیگری بیمه ندارد (مثلاً انصراف
کتبی)، در **ویرایش پرسنل** فیلد «علت نداشتن بیمه» را پر کنید تا بعداً روی
پرونده معلوم باشد.

## اقلام کارکرد

**مهاجرت:** `attendance.0005_timesheet_items` · **خودکار انجام می‌شود**

**کار دستی — فقط اگر قلم تازه‌ای می‌خواهید:** مثلاً جمعه‌کاری —

1. **تنظیمات ← اقلام کارکرد ← جمعه‌کاری ← افزودن به جدول**
2. **تنظیمات ← اقلام حقوقی ← افزودن**: نحوهٔ محاسبه «قاعده پارامتری»، مقدار
   «یک قلم جدول کارکرد» → جمعه‌کاری، مبنا و ضریب دلخواه.

## حق مسکن، وجه بن و پایه سنوات

**کار دستی — لازم بود روی نصب‌های قدیمی:**

```bash
sudo -u www-data /srv/payroll/.venv/bin/python /srv/payroll/manage.py \
    fix_component_wiring --apply
```

این سه قلم در نصب عملیاتی «مبلغ ثابت با مبلغ صفر» ساخته شده بودند و روی فیش
نمی‌آمدند. مقدارشان در **تنظیمات ← سال مالی** ثبت می‌شود.
