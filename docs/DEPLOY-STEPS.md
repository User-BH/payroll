# کارهای دستی بعد از هر به‌روزرسانی

`deploy/update.sh` کد و ساختار دیتابیس را به‌روز می‌کند، ولی **بعضی تغییرها به
یک عدد یا یک تیک نیاز دارند که فقط از پنل وارد می‌شود.** اگر آن قدم انجام نشود،
سامانه خطا نمی‌دهد — فقط آن قلم روی فیش نمی‌آید، و کسی نمی‌فهمد چرا.

این فایل فهرست همان قدم‌هاست، از تازه به قدیم. هر تغییری که ورودی دستی لازم
دارد باید همین‌جا یک سطر بگیرد، **در همان کامیتی که تغییر را می‌آورد**.

قاعده: بعد از هر به‌روزرسانی، از آخرین ردیفی که انجام نداده‌اید تا بالای فهرست
را انجام دهید، بعد دوره‌های باز را دوباره محاسبه بگیرید.

**لازم نیست حفظ کنید کدام قدم را انجام نداده‌اید.** `deploy/update.sh` در آخر
`manage.py doctor` را اجرا می‌کند و آن، زیر عنوان «اقلام حقوقی»، هر قلمی را که
فعال است ولی روی هیچ فیشی نمی‌آید با دلیلش نام می‌برد. هر وقت خواستید هم
دستی بگیریدش:

```bash
sudo -u www-data /srv/payroll/.venv/bin/python /srv/payroll/manage.py doctor
```

## زنجیرهٔ مازاد گروه پشتیبانی

**مهاجرت:** `payroll_config.0012_salarycomponent_allocation_role`

برای گروه پشتیبانی، ساعت اضافه‌کاری و روز مأموریتِ فیش **خروجی‌اند نه ورودی**.
ورودی، اضافه‌کاری *واقعی* است به‌علاوهٔ مازادها؛ سامانه آن استخر ریالی را به
روز مأموریت و ساعت اضافه‌کاری تبدیل می‌کند.

**کار دستی — بدون این، هیچ اتفاقی نمی‌افتد و اضافه‌کاری با روش قبلی می‌آید:**

1. **دو قلم ورودی استخر** بسازید (تنظیمات ← اقلام حقوقی ← افزودن):
   | | مازاد ثابت | اضافه کار مازاد |
   |---|---|---|
   | کد | `SURPLUS_FIXED` | `SURPLUS_OT` |
   | نوع | اطلاعی | اطلاعی |
   | نحوهٔ محاسبه | ورود دستی | ورود دستی |
   | ترتیب | ۱۴۶ | ۱۴۷ |
   | نقش در استخر مازاد | **به استخر اضافه می‌شود** | **به استخر اضافه می‌شود** |
   | چاپ روی فیش / بیمه / مالیات | خاموش | خاموش |
   | دامنه شمول | مراکز هزینهٔ غیرفروش | مراکز هزینهٔ غیرفروش |

2. **مابه التفاوت**: نقش → **از استخر مازاد کم می‌شود**. سطر پرداختی‌اش سر
   جایش می‌ماند؛ فقط از استخر کم می‌شود تا دو بار پرداخت نشود.
   **وجه مرخصی**: نقش → به استخر اضافه می‌شود.

3. **دو قلم خروجی** بسازید:
   - «اضافه کار (زنجیره مازاد)» — کد `OVERTIME_SURPLUS`، مزایا، قاعده موتور،
     کلید `overtime_surplus`، ترتیب ۷۱، بیمه و مالیات مثل اضافه‌کار عادی،
     دامنه: مراکز هزینهٔ غیرفروش.
   - «حق ماموریت (زنجیره مازاد)» — کد `MISSION_SURPLUS`، کلید
     `mission_surplus`، ترتیب ۸۲، دامنه: مراکز هزینهٔ غیرفروش.

4. **قلم‌های عادی را از دامنهٔ زنجیره بیرون بیاورید** — وگرنه **دو بار
   پرداخت** می‌شود:
   - «اضافه کار» (`OVERTIME`) → فقط مرکز هزینهٔ فروش
   - «حق ماموریت» (`MISSION`) → غیرفعالش کنید (فروش قلم خودش را دارد)

   صفحهٔ خلاصهٔ دوره خودش این تداخل را هشدار می‌دهد، ولی بهتر است از اول درست
   باشد.

5. **جدول کارکرد هر ماه**: برای پشتیبانی، ستون «اضافه‌کاری» را با ساعتِ
   **واقعیِ کارکرد** پر کنید، نه ساعتی که قرار است پرداخت شود. روز مأموریت
   را **خالی بگذارید** — سامانه خودش می‌سازد.

> نتیجه می‌تواند **منفی** شود، و عمدی است: اگر مابه‌التفاوت از استخر بیشتر
> باشد، روز و ساعت منفی می‌شوند. صفر کردنش یعنی مابه‌التفاوت دو بار پرداخت شود.

> باقی‌ماندهٔ گرد کردن (چند هزار ریال، معمولاً به نفع پرسنل) جبران نمی‌شود —
> مثل فایل اکسل — ولی در **توضیح همان سطر فیش** نوشته می‌شود.

## جذب مأموریت و مابه‌التفاوت در پورسانت فروش

**مهاجرت:** `payroll_config.0011_salarycomponent_absorbs`

قلم می‌تواند اقلام دیگری را **در خودش جذب** کند: مبلغشان از همان قلم کم می‌شود،
نه از خالص. فرق مهمش با کسورات این است که **ناخالص را هم پایین می‌آورد** — و در
فایل ۱۴۰۵ شرکت، پورسانت فروش دقیقاً همین‌طور بسته شده:

```
پورسانت قابل پرداخت = پورسانت خام − (مبلغ مأموریت + مابه‌التفاوت + ذخیره پورسانت)
```

**کار دستی — بدون این، پورسانت خام کامل روی فیش می‌نشیند و ناخالص بیشتر می‌شود:**

1. **تنظیمات ← اقلام حقوقی ← ذخیره پورسانت فروش**؛ اگر نیست بسازید:
   کد `COMM_RESERVE`، نوع **اطلاعی**، نحوهٔ محاسبه **ورود دستی**، ترتیب ۱۴۵،
   «چاپ روی فیش» خاموش، بیمه و مالیات خاموش، دامنه شمول مرکز هزینهٔ **فروش**.
   قلم اطلاعی سطر نمی‌سازد و در هیچ جمعی نمی‌آید — فقط عددش برای جذب لازم است.

2. **تنظیمات ← اقلام حقوقی ← پورسانت یک**:
   - نحوهٔ محاسبه → **قاعده موتور**، کلید قاعده → `commission_net`
   - «اقلامی که در این قلم جذب می‌شوند» → **حق ماموریت فروش**، **مابه التفاوت**،
     **ذخیره پورسانت فروش**
   - ترتیبش باید از «حق ماموریت فروش» بزرگ‌تر باشد (۱۳۰ در برابر ۸۱). فرم خودش
     جلوی ترتیب اشتباه را می‌گیرد.

3. **ورود دستی هر دوره**: در «پورسانت یک» عدد **خام** توافق‌شده را وارد کنید،
   نه عدد پس از کسر. کسر را خود سامانه انجام می‌دهد و در توضیح همان سطرِ فیش
   می‌نویسد چه چیزهایی و چقدر جذب شد.

> اگر نتیجه **منفی** شد، سامانه صفرش نمی‌کند — در فایل شرکت هم منفی می‌شود
> (اردیبهشت، یک نفر: ۹۸۰٬۸۴۳− ریال). یعنی جذب از خودِ پورسانت بیشتر بوده، و
> پنهان کردنش فقط اختلاف را جای دیگری ظاهر می‌کند.

> «جذب» فقط با قاعدهٔ `commission_net` خوانده می‌شود. اگر روی قلم دیگری پرش
> کنید فرم خطا می‌دهد، چون در محاسبه هیچ اثری نمی‌گذاشت و کسی نمی‌فهمید.

## مبنای اضافه‌کاری، مبنای مأموریت، و سابقه

**مهاجرت:** `employees.0008_prior_service` · `payroll_config.0010_…` ·
`attendance.0006_…`

**کار دستی — لازم:**

1. **گزارش سابقه را ببینید، پیش از هر محاسبه‌ای:**
   ```bash
   sudo -u www-data /srv/payroll/.venv/bin/python /srv/payroll/manage.py seniority_report
   ```
   سابقه دیگر عدد ثبت‌شده نیست و از تاریخ استخدام حساب می‌شود. کسی که عدد
   قدیمی‌اش کهنه شده بود ممکن است **از این ماه پایه سنوات بگیرد**. برای هرکس
   که سابقهٔ کار پیش از این استخدام دارد، «ویرایش پرسنل ← سابقهٔ قبلی (ماه)»
   را پر کنید.

2. **تنظیمات ← سال مالی**، سه کلید تازه (پیش‌فرضشان رفتار قبلی است):
   - «مبنای اضافه‌کاری» → برای این شرکت: **حقوق و سنوات ماهانه ÷ ساعات کار ماهانه**
   - «ساعات کار ماهانه» → ۲۲۰
   - «مبنای حق مأموریت» → برای این شرکت: **مزد روزانه + پایه سنوات روزانه**

3. **ضریب ۲ مأموریت فروش** (اگر می‌خواهید مثل فایل باشد): یک قلم دوم
   «حق ماموریت فروش» با نحوهٔ محاسبه «قاعده موتور»، کلید `mission_allowance`،
   نرخ ۲، و دامنه شمول مرکز هزینهٔ فروش. قلم مأموریت اصلی را هم به بقیهٔ مراکز
   محدود کنید، وگرنه هر دو با هم می‌آیند.

4. **قلم «کسر انبار»** اگر لازم دارید: تنظیمات ← اقلام حقوقی ← افزودن، نوع
   کسورات، نحوهٔ محاسبه «ورود دستی».

> بدون قدم ۲، محاسبه با روش قبلی ادامه می‌دهد و خطا نمی‌دهد — فقط اعداد با
> فایل اکسل نمی‌خواند.

## مزد روزانه به‌جای حقوق ماهانه

**مهاجرت:** `employees.0007_daily_wage` · **خودکار انجام می‌شود**

مزد قرارداد از ماهانه به روزانه تبدیل شد. مهاجرت عدد قدیمی را بر طول ماهِ آخرین
فیش صادرشده تقسیم می‌کند تا همان فیش عوض نشود.

**کار دستی — لازم:**

1. **پرسنل ← هر پرسنل ← ویرایش قرارداد**: عدد «مزد روزانه (ریال)» را یک بار
   چشمی ببینید. باید همان مزد روزانه‌ای باشد که در فایل اکسل دارید.
   اگر عدد قدیمی با مخرج دیگری وارد شده بود، اینجا معلوم می‌شود.
2. **تنظیمات ← سال مالی ← حداقل دستمزد روزانه**: پر باشد. هر قراردادی که مزد
   روزانه‌اش خالی است، از این عدد استفاده می‌کند.

> مزد روزانهٔ خالی **ایراد نیست** — یعنی «این پرسنل مزد اختصاصی ندارد».

## حق تأهل

**مهاجرت:** `payroll_config.0008_legalparameter_marriage_allowance`

**کار دستی — بدون این، حق تأهل روی هیچ فیشی نمی‌آید:**

1. ```bash
   sudo -u www-data /srv/payroll/.venv/bin/python /srv/payroll/manage.py \
       fix_component_wiring --apply
   ```
   قلم «حق تاهل» را از «مبلغ ثابت با مبلغ صفر» به قاعدهٔ موتور وصل می‌کند.
2. **تنظیمات ← سال مالی ← حق تأهل ماهانه**: مبلغ را وارد کنید (در فایل ۱۴۰۵
   شرکت: ۵٬۰۰۰٬۰۰۰ ریال). **صفر یعنی این قلم را ندارید** و سطرش نمی‌آید.
3. **تنظیمات ← اقلام حقوقی ← حق تاهل**: اگر دامنه شمولی دارد که به کسی نمی‌خورد
   (مثلاً «موقت» در حالی که همه دائم‌اند) حذفش کنید. صفحهٔ خلاصهٔ دوره حالا
   خودش این را هشدار می‌دهد.
4. **پرسنل**: وضعیت تأهل هر کس درست ثبت شده باشد — حق تأهل فقط به «متأهل»
   تعلق می‌گیرد.

## اقلام کارکرد

**مهاجرت:** `attendance.0005_timesheet_items` · **خودکار انجام می‌شود**

**کار دستی — فقط اگر قلم تازه‌ای می‌خواهید:** مثلاً جمعه‌کاری —

1. **تنظیمات ← اقلام کارکرد ← جمعه‌کاری ← افزودن به جدول**
2. **تنظیمات ← اقلام حقوقی ← افزودن**: نحوهٔ محاسبه «قاعده پارامتری»، مقدار
   «یک قلم جدول کارکرد» → جمعه‌کاری، مبنا و ضریب دلخواه.

    fix_component_wiring --apply
